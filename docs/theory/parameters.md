# Происхождение параметров

У параметров проекта три разных источника. Физическая формула задаёт связь величин; публикация обосновывает область применимости; конкретная сцена задаёт численные предположения. Эти уровни нельзя подменять друг другом.

## Где смотреть обоснование

Физические и модельные константы собраны в `src/physical_constants.py` с комментариями и ссылками. Численные значения примеров сцен сопровождаются полем `_provenance`: ключи указывают на параметры JSON, а записи объясняют происхождение и статус значения.

| Группа | Что означает |
| --- | --- |
| Физическая константа | Принятое значение в системе СИ, например электрическая постоянная |
| Коэффициент модели | Часть опубликованной формулы, применимая вместе с её предпосылками |
| Параметр материала | Значение, которое для реальной площадки надо измерить или подобрать по данным |
| Сценарное допущение | Выбранная толщина, влажность, размер цели или масштаб неоднородности |
| Численный параметр | Шаг сетки, число материалов, PML, ограничение памяти или точности |

## Что не следует из статьи автоматически

CRIM/Archie не определяют проводимость воды, плотность, влажность или толщину асфальта конкретной сцены. Работа о коррелированных полях не доказывает, что именно 25 см — правильная длина корреляции для любого парка. Такие значения в примерах являются входными допущениями, а не результатами измерений.

Для минерального грунта проверяются доли песка и глины, плотность и диапазон влажности. Плотность частиц 2.66 г/см³ используется в принятой реализации Peplinski; это параметр модели минерального грунта, а не универсальная плотность всех почв. Пористость оценивается как `1 − bulk_density / particle_density`.

Проницаемость воды около 80 в недисперсионном CRIM — приближение. Сравнение с дисперсионным Peplinski выполняется на явно указанной частоте. Аналогично тестовая сфера с фиксированными `εr` и `σ` — условное включение, а не характеристика всех пластиков.

## Как менять параметры

1. Скопировать пример сцены.
2. Изменить физические параметры и обновить соответствующее обоснование в `_provenance`.
3. Создать новый эксперимент и проверить предпросмотр.
4. Для численных настроек сравнить результат при более мелкой сетке, большем окне или более толстом PML.
5. Для соответствия реальному прибору сравнить с независимыми контрольными измерениями.

Поле `_provenance` документирует выбор; оно само по себе не делает постановку физически правильной. [Публикации и область их применения](papers.md).
