# Траектория

Маршрут — отдельный JSON. Координаты `[x, y]` получают высоту `surface_z + source.height_m`; `[x, y, z]` задают её явно. Rx смещён относительно Tx по глобальной оси +X. Ориентация диполя фиксирована и не поворачивается вслед за змейкой.

Положения округляются к `solver_dx`. Соседние позиции, попавшие в одну ячейку Tx, объединяются. Заданные и фактические координаты сохраняются в `trajectory.csv` и `positions.npz`. `step_m` — максимальный шаг до округления; конечная точка каждого отрезка включается, поэтому последний интервал может быть короче.

## Прямая

```json
{"type": "line", "start": [1, 1], "end": [5, 1], "step_m": 0.05}
```

Пример: `examples/trajectories/line.json`.

## Змейка

```json
{
  "type": "snake",
  "start": [1, 1],
  "row_length_m": 4,
  "rows": 4,
  "row_spacing_m": 0.3,
  "step_m": 0.05,
  "turn": "rounded",
  "heading_deg": 0
}
```

`row_length_m` — длина прямого прохода, `rows` — число проходов, `row_spacing_m` — расстояние между ними. `heading_deg` поворачивает всю траекторию на плане. `turn` принимает `straight` или `rounded`: прямой соединитель либо полукруг. Повороты входят в последовательность измерений и отмечаются отдельным сегментом.

Пример: `examples/trajectories/snake.json`.

## Ломаная через точки

```json
{
  "type": "waypoints",
  "points": [[1, 1], [3, 1], [3, 2], [5, 2]],
  "step_m": 0.05
}
```

Программа добавит промежуточные измерения между вершинами. Для измерений только в перечисленных позициях используйте `type: "points"` без `step_m`.

Примеры: `waypoints.json` и `points.json` в `examples/trajectories/`.

## CSV

```json
{"type": "csv", "file": "coords.csv", "step_m": 0.05}
```

Файл ищется относительно JSON маршрута. Заголовок CSV — `x_m,y_m` либо `x_m,y_m,z_m`. С `step_m` строки интерпретируются как вершины ломаной; без него используются только исходные позиции. При `init` координаты сохраняются внутри эксперимента, поэтому исходный CSV потом не нужен для продолжения расчёта.

## Случайные позиции

```json
{
  "type": "random",
  "bounds_m": [[1, 5], [1, 3]],
  "count": 30,
  "seed": 42,
  "method": "poisson_disk",
  "min_distance_m": 0.25,
  "order": "nearest"
}
```

Доступны `uniform`, `sobol`, `poisson_disk`. Метод Пуассона здесь — отбор равномерных кандидатов с минимальным расстоянием, без обещания максимальной упаковки. `order: "sample"` сохраняет порядок выборки; `nearest` последовательно выбирает ближайшую следующую точку. Это порядок обследования, а не оптимальный маршрут коммивояжёра.

`min_distance_m` проверяется для запрошенных координат. Округление к `solver_dx` может немного уменьшить расстояние между фактическими позициями; для строгого ограничения учитывайте шаг сетки и проверяйте экспортированные координаты.

Между случайными позициями дополнительные измерения не добавляются. Такой набор удобен для пространственного датасета; он не заменяет непрерывную запись движения для задачи одометрии. Примеры: `random-poisson.json`, `random-sobol.json`.

## Несколько маршрутов

```json
{
  "routes": [
    {"type": "line", "name": "forward", "start": [1, 1], "end": [5, 1], "step_m": 0.05},
    {"type": "line", "name": "reverse", "start": [5, 1.3], "end": [1, 1.3], "step_m": 0.05}
  ]
}
```

Количество маршрутов произвольное. `route_id` различает маршруты, `segment_id` — участки. Накопленный путь `distance_m` начинается с нуля для каждого маршрута. B-сканы строятся отдельно; в одном изображении размещаются до четырёх маршрутов, остальные — на следующих страницах.

## Проверить перед расчётом

```bash
python geodatagen.py init survey --scene examples/scenes/park.json --trajectory examples/trajectories/snake.json
python geodatagen.py docs survey
```

Проверьте старт, порядок движения, положение целей и отступ от краёв. В режиме движущегося окна внутри глобальной сцены должно помещаться всё окно, а не только Tx/Rx.
