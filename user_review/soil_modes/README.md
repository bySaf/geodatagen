# Два режима генерации грунта

В основной программе доступны `native_peplinski` и `custom_crim_archie`. Расчётные данные `data/final` содержат только первый режим. Второй теперь подключён из файла `/Users/davsf/Downloads/to_send/gpr_fields.py`, который пользователь подтвердил как модель полей. В `src/supervisor_fields.py` сохранены происхождение и SHA-256 исходника.

| Режим | Пространственная структура | Электрофизические свойства |
|---|---|---|
| `native_peplinski` | Штатный `fractal_box`, плоские границы слоёв | Штатный дисперсионный Peplinski gprMax |
| `custom_crim_archie` | Спектральное коррелированное поле, масштабы по трём осям, связанные пористость/насыщение, неровные внутренние границы | Приближённые недисперсионные CRIM и Archie с добавкой поверхностной проводимости |

Peplinski — модель связи состава/влажности с электрофизическими свойствами, а не название алгоритма случайного поля. Здесь при переключении меняются **оба** компонента: пространственная генерация и преобразование в свойства. Второй режим автоматически не становится точнее первого.

## Выбор и подготовка

Из корня проекта:

```bash
# Исходный полный размер 7 × 4.8 × 1.2 м; только подготовка геометрии.
.venv/bin/python main.py prepare --config user_review/soil_modes/project-native.json --data data/native_new
.venv/bin/python main.py prepare --config user_review/soil_modes/project-custom.json --data data/custom_new
```

В конфигурации переключатель — `soil_generator`. Для отдельной сцены можно задать `generator` непосредственно в её пресете. Не используйте `data/final` для другой конфигурации: программа защищает уже рассчитанный набор от смешивания. `prepare` не рассчитывает A-сканы. Для нового набора нужен отдельный `run`.

## Что означают параметры второго режима

- `custom.water_conductivity_s_m` обязательно задаётся явно. Её нельзя получить только из долей песка/глины и диапазона влажности.
- По умолчанию пористость берётся как `1 − bulk_density / 2.66`, а средняя насыщенность — как средняя объёмная влажность, делённая на пористость. Стандартное отклонение насыщенности строится из ширины исходного диапазона как для равномерного распределения. Это правило сопоставления входов, а не подгонка к данным.
- `water_min/water_max` в custom задают исходные моменты. Полученное гауссово поле после физических ограничений может выходить за этот диапазон. Фактические минимум/среднее/разброс сохраняются в проверках.
- В примере явно приняты поровая проводимость 0.12 См/м, проводимость поверхности 0.0005 См/м, параметры Archie `a=1, m=1.5, n=2`, проницаемость зёрен 4.5 и воды 80. Это иллюстративные значения исходной модели, **не измеренные свойства парка/поля/дороги**. Для глинистых грунтов особенно нужна калибровка потерь.
- `custom.correlation_m` задаёт характерные масштабы неоднородностей X/Y/Z в метрах. Это не строго подтверждённые диапазоны ковариации; их следует проверять на полученном поле.
- `custom.roughness_rms_m` и `roughness_corr_m` задают неровность нижней границы слоя. Внешняя поверхность остаётся плоской, поскольку текущий маршрут держит постоянную высоту Tx/Rx.
- Асфальт и основание сохраняют заданные постоянные ε/σ. Peplinski или CRIM не применяются к ним как к минеральной почве.

## Готовое сравнение

`soil_modes_comparison.png` — вертикальные срезы трёх типов грунта в обоих режимах на общей шкале ε. Сравнение использует одну область **2 × 1.2 × 1.2 м**, шаг 2 см, одну номинальную стратиграфию и одинаковые seed. Объекты отключены, чтобы показать именно грунт. Это отдельные маленькие примеры, **не замена сценам с 4500 готовыми A-сканами**.

Для native показана действительная ε на 400 МГц с учётом Дебая, для custom — его постоянная ε. Карты извлечены из материалов, реально экспортированных gprMax, после дискретизации свойств. Одинаковый seed не означает одинаковую реализацию у разных генераторов.

Геометрия находится в `preview_geometry/<режим>/<сцена>/scene.vtkhdf`. Полная воспроизводимая сцена включает также `scene.in`, `global.h5` и файлы материалов рядом. `build_comparison.py` пересоздаёт только эти шесть примеров, без FDTD. `comparison_checks.json` содержит фактическую статистику влажности и контрольные суммы геометрии.

Для повторного построения картинки по уже готовым данным: `.venv/bin/python user_review/soil_modes/build_comparison.py --plot-only`. Глубина на рисунке возрастает вниз, ноль — поверхность, отрицательные значения — воздух. Границы асфальта и основания дороги оставлены плоскими в обоих режимах; параметр шероховатости применяется к внутренним границам минеральных слоёв. В этой дороге минеральный слой один, поэтому неровной внутренней границы у него нет.

В custom папке `custom_fields.npz` сохраняет непрерывное исходное поле. Его ε/σ описывают грунт **до добавления объектов**; фактические квантованные материалы и объекты берите из `global.h5`/`global_materials.json`. В статистике влажности объекты исключены маской.

## Ресурсы и ограничения

Полная область 350 × 240 × 60 ячеек требует FFT на 40 320 000 точках из-за увеличения каждой оси вдвое. Лимит по умолчанию — 50 000 000; ожидается несколько гигабайт временной памяти. Генерацию больших сцен выполняйте последовательно. Увеличение разрешения резко увеличивает память; превышение лимита останавливает подготовку с понятной ошибкой.

Выбор второго режима ещё не подтверждает улучшение сходства A-сканов с реальным радаром. Нужны отдельные проверки влияния пространственных масштабов, дисперсии и проводимости. Полученные примеры проверяют воспроизводимость, экспорт и структуру, а не реальную точность.
